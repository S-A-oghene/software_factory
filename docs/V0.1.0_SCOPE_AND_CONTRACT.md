# v0.1.0 Scope and Contract

## Purpose

v0.1.0 is the **minimum viable autonomous engineering factory**, not merely a coding agent.

## Mandatory outcomes

The factory must be able to accept:

- a fresh structured specification;
- an existing repository;
- an existing ZIP bundle of a shipped solution;
- human-provided engineering notes;
- artifacts returned from a browser-based frontier LLM session.

It must be able to produce:

- an engineering model;
- a requirements graph;
- a capability graph;
- an architecture plan;
- an implementation plan;
- a workspace modification set;
- validation evidence;
- benchmark evidence;
- an exportable release bundle.

## What 'cutting-edge' means in this contract

The factory is not entitled to label an output state of the art on intuition. It must provide a comparison package against a reference architecture/implementation or a clearly defined research/frontier rubric.

The acceptable language is:

- **demonstrated parity** — metrics meet the reference target on the defined benchmark;
- **demonstrated superiority on a dimension** — a measured metric is better than the reference on the same test and test population;
- **unverified frontier hypothesis** — technically plausible but not experimentally demonstrated;
- **open research problem** — evidence does not establish a reliable general solution.

## v0.1.0 non-goals

- unrestricted automation of third-party consumer web GUI accounts;
- claiming universal superiority over all industry systems;
- direct unvalidated control of motors, robots, industrial machinery or hazardous processes;
- replacing mature databases, queues, simulators or orchestrators with fragile home-grown clones.
